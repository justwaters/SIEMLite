Threat intel

SIEMLite checks every event against a list of indicators: IP addresses, CIDR ranges, domains (which also match subdomains) and MD5/SHA-1/SHA-256 hashes. It looks at the source and destination IPs and at IPv4 addresses, domain names and hashes anywhere in the raw log. A hit marks the event as a threat (red bar and INTEL badge in the UI, threat=true in search) and records which indicator, source and field matched, plus what each list says about it: the list's name, the kind of threat it tracks (botnet C2, Tor exit node, brute-force attacker…), how far to trust it (high, medium or low), a link to read about it, and the feed's own note for that line (for example "Possible Cobaltstrike C2 IP"). An address on several lists shows every one. Hover an underlined IP (in the Database, alerts, the Dashboard and reports) to see where it is and which lists it is on.

The easy way: the Intel page (admins). Its Threat feeds section lists free IP blocklists that need no account (Feodo Tracker, C2IntelFeeds, IPsum, two from Blocklist.de, and the Tor exit nodes). Tick the ones you want and save: they download right away, refresh every 6 hours, and are removed again if you untick them. A list is downloaded again only when its last download is 6 hours old, so restarting or updating SIEMLite, or choosing another list, doesn't download the others again (the Refresh button does, whatever their age). Each has a link to its provider's terms; whether you may use a list where you work is your call. Nothing is downloaded until you choose it. Events show the feed's name as the source of a match. Tor exit nodes aren't malicious in themselves, but they are flagged like any other listed address, so the built-in Threat intel match rule raises a High alert for each address that hits (traffic from or to a Tor exit; put your own exits on a friendly list to leave them alone).

Friendly addresses (same page) are lists of addresses and ranges you trust, such as your office, a partner or a scanner you run. Make a list, then paste addresses (one per line, or separated by commas; 203.0.113.7 or 198.51.100.0/24; # starts a comment). A friendly address is never marked as a threat, even when a feed lists it. It applies to events stored from then on; events already in the database keep their marks. To add an address from anywhere in the UI, right-click it and choose Add to list (see IP addresses in the UI).

Or download feeds from the command line (refreshed every -intel-refresh, default 6h; these show on the Intel page too, read-only):

./siemlite \
  -intel-feed feodo=https://feodotracker.abuse.ch/downloads/ipblocklist.txt \
  -intel-feed drop=https://www.spamhaus.org/drop/drop.txt \
  -intel-feed urlhaus=https://urlhaus.abuse.ch/downloads/hostfile/

Or manage indicators from the command line (works while the server is running; changes are picked up within 30s):

./siemlite intel import -source mylist -file iocs.txt     # replaces everything in "mylist"; -file - reads stdin
./siemlite intel import -source feodo -url https://feodotracker.abuse.ch/downloads/ipblocklist.txt
./siemlite intel add -source manual -value 203.0.113.7 -description "seen in phishing"
./siemlite intel list
./siemlite intel delete -source mylist

Feed files have one indicator per line. Plain lists, CSV (first column), Spamhaus DROP (1.2.3.0/24 ; SBL123), hosts files (0.0.0.0 evil.example) and URL lists (the host is used) are understood; comments and invalid lines are skipped. The type is detected, or forced with -type ip|cidr|domain|hash. Importing or refreshing a source replaces all of its indicators, so entries removed from a feed stop matching. A download that fails or comes back empty keeps the previous indicators.

Matching happens when an event is stored; adding an indicator does not flag older events (search for it instead).
