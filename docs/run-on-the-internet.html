Run on the internet

To serve SIEMLite on a public domain, let Caddy be its web server. Caddy gets a certificate from Let's Encrypt, renews it by itself, and redirects plain HTTP to HTTPS. SIEMLite's web ports then aren't published at all: only Caddy can reach SIEMLite, over a private port on the Docker network. Before you start:

  • A DNS name (an A or AAAA record) that points at this server, such as siem.example.com.
  • Ports 80 and 443 reachable from the internet. Let's Encrypt connects to one of them to check you control the name.

Then add to .env and run docker compose up -d:

COMPOSE_FILE=compose.yaml:compose.public.yaml
SIEMLITE_DOMAIN=siem.example.com

Open https://siem.example.com. Caddy gets the certificate on that first visit (usually within seconds); docker compose logs caddy shows it.

Changing the domain is done on the System page, under Web address; no restart or file edit is needed. Caddy asks SIEMLite before it gets a certificate for any name, and SIEMLite agrees only to the domain set there (or, until one is, SIEMLITE_DOMAIN), so nobody can make Caddy request certificates for names that aren't yours. When you move to a new domain, visitors who use the old one are redirected to it. SIEMLITE_DOMAIN is still needed in .env: it is where SIEMLite starts, since it can't be reached any other way.

  • Visitors' addresses reach SIEMLite in X-Forwarded-For, which it believes only from Caddy (-trusted-proxies=caddy), so sign-in lockouts apply to the person who failed, not to everyone, and the audit log shows who it was. Caddy throws away any X-Forwarded-For a visitor sends, so it can't be forged, and SIEMLite's plain port refuses anyone but Caddy. Caddy runs on a Docker network (edge) that only SIEMLite shares, so no other container can ever take an address SIEMLite trusts as Caddy's; don't add other services to it.
  • Syslog is still published on its own ports, and senders outside loopback and private networks are refused unless you list them in SIEMLITE_SYSLOG_ALLOW. Don't open syslog to the internet: it has no authentication. Syslog over TLS keeps SIEMLite's own certificate.
  • Apps sending logs use https://siem.example.com/api/v1/logs. The certificate is trusted everywhere, so the snippets on the Connect screen work without siemlite.crt; remove those lines.
  • Microsoft sign-in: set the SIEMLite address on the Entra card to https://siem.example.com.
  • Caddy keeps the certificate in the caddy-data volume; keep it, or Caddy asks Let's Encrypt again on every rebuild. It adds Strict-Transport-Security and compresses responses. To change anything else, edit caddy/Caddyfile.
  • Inside the Docker network SIEMLite still serves HTTPS on 8443 (the health check and the log generator use it); it is not published.
  • Not for a private network with no public name: Let's Encrypt can't reach it. Keep the default setup there.
