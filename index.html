A SIEM in a single Go binary.

Collect, search and retain security logs with one executable and one SQLite file. No cluster, no agents to babysit, no cloud bill.

Everything a small team needs to see what happened

SIEMLite is built for homelabs, small companies and single services where a full SIEM stack is overkill.

Send any log

Post syslog, JSON lines or plain text. SIEMLite detects the timestamp, hostname, IPs, user and severity, and keeps your original line verbatim.

OCSF-normalized

Events are stored in the Open Cybersecurity Schema Framework model, so categories, classes and severities mean the same thing across every source.

Fast full-text search

SQLite FTS5 with phrase, boolean and prefix queries, combined with time-window, severity, category, IP and user filters.

Built-in web UI

Search, expand any event to see the raw log, paste or upload logs, and watch ingest health live. It's embedded in the binary.

High-throughput ingest

Events are queued and written to SQLite in batched transactions (500 events or 500 ms, whichever comes first) over a WAL database.

Automatic retention

Logs older than your retention window (30 days by default) are deleted in batches, and disk space is returned with incremental vacuum.

HTTPS only

There is no plain-HTTP listener. A self-signed certificate is generated on first start, or bring your own.

Scoped API keys

Write-only keys for your apps, read keys for analysts, admin keys for you. Keys are stored hashed and shown once.

Pure Go, no CGO

Built on modernc.org/sqlite, so it cross-compiles cleanly and ships as one static-friendly binary.

Quick start

From clone to first search in about a minute. Requires Go.

  1. Build and run

    git clone https://github.com/justwaters/SIEMLite.git
cd SIEMLite
go build -o siemlite .
./siemlite

    On first start SIEMLite creates siemlite.db, a self-signed certificate, and prints an admin API key once. Copy it. The UI is at https://localhost:8443.

  2. Create a write-only key for your app

    ./siemlite keys create -name myapp -role write

  3. Point your app at it

    # send a log file
curl --cacert siemlite.crt -X POST \
  'https://localhost:8443/api/v1/logs?source=myapp' \
  -H "Authorization: Bearer $SIEMLITE_KEY" \
  --data-binary @app.log

# or send structured OCSF events
curl --cacert siemlite.crt -X POST https://localhost:8443/api/v1/events \
  -H "Authorization: Bearer $SIEMLITE_KEY" \
  -d '[{"category_uid":3,"class_uid":3002,"severity_id":4,
        "message":"Failed password for root","src_endpoint":{"ip":"203.0.113.7"}}]'

  4. Search

    Open the UI and sign in with a read or admin key, or query the API:

    curl --cacert siemlite.crt -H "Authorization: Bearer $SIEMLITE_READ_KEY" \
  'https://localhost:8443/api/v1/search?q=failed+AND+ssh&severity=3&limit=20'

The API

Four endpoints. JSON in, JSON out.

EndpointRolePurpose
POST /api/v1/logswriteRaw log text, one entry per line (syslog, JSON lines, plain text)
POST /api/v1/eventswriteArray of OCSF events
GET /api/v1/searchreadq, start, end, severity, category, src_ip, dst_ip, user, limit, offset
GET /healthpublicUp/down for load balancers; counts and queue state with a read key

Secure by default

A log store is a juicy target, so SIEMLite starts locked down.

No plaintext, ever

The server only speaks TLS 1.2+. There is no HTTP port to forget to close.

Least-privilege keys

An app that can write logs can't read them. A compromised app key doesn't expose your history.

Hashed at rest

Only a SHA-256 of each key is stored. Revoke any key instantly with siemlite keys revoke.

Early-stage project. Client-certificate (mTLS) verification and per-key rate limiting are not implemented yet.
