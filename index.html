SIEMLite
See it Features Quick start Security GitHub

A SIEM in a single Go binary.

Collect logs over HTTPS or syslog, check every event against threat intel, and search it all from a built-in web UI. One executable, one SQLite file, and one command to run it with Docker.

See it

These screenshots are from SIEMLite itself, running its built-in sample data: a day of normal traffic with an intrusion hidden in it. Turn on Sample data in the sidebar to explore the same events yourself.

One search field to start

The search page opens empty, with nothing but the field. Type words, “exact phrases” or failed AND ssh, or press Enter to see the latest events. Filters for time, severity, IPs, users, sources and countries are a click away.

Threats stand out

Colour only ever means severity, so a red edge is impossible to miss. Every event is checked against threat intel blocklists as it arrives, and opening one explains the match in a sentence, next to the IP’s location, its network and the raw log line. Light and dark themes are both built in.

Check in from your phone

On a small screen, the table shrinks to the time, severity and message, and the sidebar becomes a menu. Here, a search for "failed password" shows a brute-force attack against one server.

Everything a small team needs to see what happened

SIEMLite is built for homelabs, small companies and single services where a full SIEM stack is overkill.

Send any log

Post logs over HTTPS, or point rsyslog, syslog-ng, firewalls and switches at its syslog listener over UDP, TCP or TLS. Syslog, JSON lines and plain text all work, and every original line is kept verbatim.

Threat intel matching

Every event is checked against IP, IP range, domain and file hash blocklists. Load feeds like abuse.ch and Spamhaus automatically, or import your own lists. A match is flagged and explained.

GeoIP and network owner

Add a free MaxMind or DB-IP database and every public IP gets a country, city and network (ASN). Search by country or network, like country=CN.

Fast full-text search

SQLite FTS5 with phrase, boolean and prefix queries, plus filters for time, severity, category, IPs, user, source, host, country, network and threat matches.

A quiet web UI

Start from one search field, open any event for its full context, and add logs by pasting or uploading a file. Light and dark themes, and it works on a phone. It’s built into the binary.

Sample data to explore

Not sending logs yet? Turn on Sample data for a day of realistic events with an intrusion to investigate. Turn it off and only the sample is removed.

OCSF-normalized

Events follow the Open Cybersecurity Schema Framework, so categories, classes and severities mean the same thing across every source.

Docker in one command

docker compose up -d --build runs it, and the same command after a git pull upgrades it. Data lives in a volume, and settings go in one .env file.

Automatic retention

Events older than your retention window (30 days by default) are deleted in batches, and the disk space is given back.

Quick start

From clone to first search in about a minute.

  1. Run it

    With Docker:

    git clone https://github.com/justwaters/SIEMLite.git
cd SIEMLite
cp .env.example .env    # optional settings
docker compose up -d --build

    Or build it with Go: go build -o siemlite . then ./siemlite.

  2. Sign in

    On first start, SIEMLite creates an admin account and prints its password once:

    docker compose logs siemlite | grep -A1 'username: admin'

    Open https://your-server:8443 and sign in. Turn on Sample data in the sidebar to look around before real logs arrive.

  3. Send it logs

    From any Linux machine with rsyslog, forward everything over TCP:

    # /etc/rsyslog.d/siemlite.conf
*.* @@your-server:514

    Or from an app, with an API key that can only send logs:

    docker compose exec siemlite siemlite keys create -name myapp
docker compose cp siemlite:/data/siemlite.crt .

curl --cacert siemlite.crt -X POST \
  'https://your-server:8443/api/v1/logs?source=myapp' \
  -H "Authorization: Bearer $SIEMLITE_KEY" \
  --data-binary @app.log

  4. Add threat intel

    List blocklist feeds in .env; they’re downloaded now and refreshed every 6 hours:

    SIEMLITE_INTEL_FEED=feodo=https://feodotracker.abuse.ch/downloads/ipblocklist.txt drop=https://www.spamhaus.org/drop/drop.txt

    Then run docker compose up -d again. Matching events are flagged as they arrive.

The API

JSON in, JSON out. Apps send logs with API keys; everything else needs a signed-in user.

EndpointWhoPurpose
POST /api/v1/logsAPI key or adminRaw log text, one entry per line (syslog, JSON lines, plain text)
POST /api/v1/eventsAPI key or adminAn array of OCSF events, up to 10,000 per request
GET /api/v1/searchsigned-in userFull-text query plus time, severity, category, IP, user, source, host, country, network and threat filters
GET / POST /api/v1/samplesigned-in user / adminSee whether sample data is loaded, or turn it on and off
GET /healthpublicUp or down for load balancers; counts, queue, intel and syslog figures when signed in

Secure by default

A log store is a juicy target, so SIEMLite starts locked down.

No plaintext web

The web UI and API only speak TLS 1.2 or newer, and there is no HTTP port to forget to close. Syslog can use TLS too.

Least-privilege keys

An app that can send logs can’t read them, so a leaked app key doesn’t expose your history.

Hashed at rest

Passwords are stored as bcrypt hashes and API keys as SHA-256 hashes. Sessions end on sign-out, and repeated failed sign-ins are locked out.

Syslog allowlist

Syslog has no login, so only senders on private networks are accepted unless you list others.

A small, unprivileged image

The Docker image is about 25 MB, has no shell, and runs as a non-root user.

Checked on every change

Every pull request runs the tests, a race detector, a build of the Docker image and Go’s vulnerability scanner.

Early-stage project. Client-certificate (mTLS) verification and per-key rate limiting on log ingest are not implemented yet.
